# ぶっ飛ばせ！ムカつくアイツ！ ゲーム実装仕様書 Ver.2.1

## 1. 企画・ターゲット
スマホ縦画面9:16のハイパーカジュアルゲーム。5回固定の超短時間ミニゲームでパンチ威力を決め、架空のコミカルな相手を遠くへ飛ばす。飛行は完全自動。GitHub Pagesで公開する。対象は短いプレイ時間と派手な成功演出を好むユーザー。

## 2. 確定ゲームフロー
HOME → SELECT → MINIGAME（5回） → PUNCH → FLIGHT（操作なし） → RESULT → リトライ/選択。
標準26秒（対戦開始1秒、ミニゲーム12秒、パンチ2秒、飛行8秒、結果3秒）。飛行演出のスキップは可能だが距離に影響しない。
同一プレイでは6種から5種を重複なしで抽選。ミニゲーム間の遷移は0.3秒以内を目標。

## 3. ミニゲーム仕様
|ID|名称|操作|制限|
|---|---|---|---|
|01|ジャストバー|左右往復する針が中央に来たらタップ|2.0秒|
|02|ストップリング|縮小リングが目標円と重なる瞬間タップ|2.0秒|
|03|パワー連打|画面を連打、8/12/16回を基準に評価|2.5秒|
|04|ピタ止めゲージ|上下するゲージを最大値付近で停止|2.0秒|
|05|光速リアクション|0.5～1.2秒後のNOW表示に反応|最大2.0秒|
|06|3連ジャスト|3つの到達タイミングに合わせてタップ|3.0秒|

すべて精度スコア0～100に変換。PERFECT 95～100=300点、GREAT 80～94=200点、GOOD 50～79=130点、MISS 0～49=50点。未入力・早押しはMISS。初回のみ短い操作ヒントを表示。入力はpointerdown、時間計測はperformance.now()を基準にする。連打は複数ポインタ同時押しを二重計上しない。

## 4. パワー・コンボ
初期パワー100。5ラウンドの評価ポイントを加算する。PERFECTが連続した際、2/3/4/5連続到達時にそれぞれ100/200/300/500点を一度だけ加算。GOOD/GREAT/MISSで連続数をリセット。5回すべてPERFECTなら合計2700 POWER、GOD PUNCH演出。最大値を超える加点はしない。

## 5. 飛距離・演出
最終飛距離(km)=round(0.1*POWER^2.4)。ランキング上のランダム補正なし。飛行開始時に最終距離を確定し、画面表示のみ0→最終値へイージング。飛行8秒：0–0.5衝撃、0.5–2地上、2–4大気圏、4–6宇宙/到達距離に応じた背景、6–7減速、7–8着地/距離確定。短距離では未到達エリアを表示しない。ステージ境界は演出用で実距離に対応させる。
注意：上式で2700 POWERの最大飛距離は約1,720万km。『銀河の向こうまで』は現行バランスでは到達しないため、銀河到達を実現するには飛距離式またはステージ演出のスケールを別途再調整すること。銀河突破を既成仕様として誤実装しない。

## 6. キャラクター
架空人物10体の表情違い。全員同じ当たり判定・計算。初期画像は同梱の参考用ポートレート素材。これらはコンセプト図から切り出した透過の楕円マスク付き胸上ポートレートで、全身立ち絵ではない。製品版には高解像度の全身差分・パンチ被弾差分・飛行ポーズを別途制作する。
写真アップロードは端末内処理のみ。PNG/JPEG/WebP→人物セグメンテーション（ONNX Runtime Web等）→プレビュー→手動トリミング救済→IndexedDB保存。写真はサーバーへ送らず、本人の許可のある写真に限定。公開ランキング/共有画像にはアップロード顔写真を載せない。

## 7. 画面UI
wireframes/に6画面の縦型画像を収録。背景は濃紺、アクションは黄色、成功は金色、パワーは黄色。文字は大きく、親指で押せる広いタップ領域。HOME/SELECT/MINIGAME/PUNCH/FLIGHT/RESULTをPhaser Sceneとして実装する。アクセシビリティとして光刺激軽減・音量・画面揺れ軽減を設定に設ける。

## 8. サウンドと演出
PERFECT時は0.15秒のヒットストップ、文字拡大、金色粒子、短い重低音。5ラウンド進行に応じて拳のチャージが段階的に強まる。最終パンチはチャージ→超スロー→衝撃波→飛行開始。音声はユーザー操作後にアンロックする。60fps目標、低性能端末30fps許容。

## 9. 技術構成
HTML/CSS/JavaScript、Phaser 3、Vite、GitHub Pages。キャラ保存はIndexedDB。ランキングはFirebase Firestore＋匿名認証。Firestoreへクライアント計算値を直接書かせるだけでは不正対策にならない。正式ランキングではサーバー側の検証、レート制限、Firestore Rules、App Check等を設計する。日次は日本時間0時境界。公開時に写真をアップロードしないプライバシー方針を明記。

## 10. シーン遷移と状態
HOME→SELECT→MINIGAME→PUNCH→FLIGHT→RESULT。RESULTからMINIGAMEへ再挑戦、SELECTへキャラ変更、HOMEへ戻る。ゲーム状態: sessionId, characterId, miniGames[], currentRound(0–5), power, perfectStreak, maxPerfectStreak, godPunch, finalDistanceKm, finished。ラウンド確定処理は二重実行防止。

## 11. 開発フェーズとテスト
P1: 起動/シーン遷移。P2: ミニゲーム6種・5回固定・抽選重複なし。P3: パワーとコンボ・境界値テスト。P4: パンチ/飛行/リザルト・短距離/最大距離テスト。P5: プリセット10体/写真処理/端末内保存。P6: Firebaseランキング/権限/不正対策。P7: GitHub Pagesデプロイ/実機iPhone・Android確認。
各フェーズで自動テストと操作テストを実施し、失敗修正後に次へ進む。実機操作できない場合は未検証と記録。

## 12. アセット指示
references/は色・テンション・演出の参考。wireframes/は配置と画面遷移の基準。characters/は架空人物の透過ポートレートの仮素材。実装時は、見た目の参考と実際のアセット仕様を混同しない。画像内のテキストや数値は参考であり、正規仕様は本Markdownとdata/game_config.jsonが優先。

## 13. 受入基準
スマホ縦画面で5ラウンドが途切れず動く。タップ遅延・判定幅・タイムアウトのテストに合格。全PERFECT時2700 POWER。飛行操作不要、スキップで飛距離不変。画像がサーバーへ送信されない。リトライ1秒以内。ランキング権限が適切。演出軽減が機能。GitHub Pages上で相対パスを含め正常動作。
